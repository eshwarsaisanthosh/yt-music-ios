# YTMusic — personal iOS music player (client)

Native SwiftUI client for the private [yt-music-server](../yt-music-server)
backend. Paste a YouTube URL, the server splits it into ALAC tracks via the
video's chapters, and this app plays them — with background audio, lock-screen
controls, and offline downloads.

> **Environment note:** this was written on a Linux VM with no Xcode, so it
> has **not been compiled**. It is careful, idiomatic Swift (iOS 17+,
> Swift 5.9+) that should build on a Mac, but expect the usual first-build
> fixes. See "API uncertainties" below.

```
    DownloadManager.swift    background URLSession downloads → app sandbox
    LibraryStore.swift        @MainActor library cache + all mutations
  Views/
    ContentView.swift        TabView + mini player + now-playing sheet
    LibraryView.swift        videos list + VideoDetailView (tracks)
    PlaylistsView.swift      playlists CRUD + PlaylistDetailView (reorder, offline toggle)

```

## Architecture

```
Views → LibraryStore (@MainActor cache)
        → APIClient (network) · PlaybackEngine (AVQueuePlayer) · DownloadManager
```

- **Streaming:** `AVPlayerItem` built from `GET /v1/tracks/{id}/stream`. When an
  API token is configured, it is injected via `AVURLAssetHTTPHeaderFieldsKey`
  (AVPlayer can't set headers on a bare URL). Downloaded tracks play from disk.
- **Offline:** per-track background downloads; per-playlist "Download for
  offline" toggle auto-downloads new tracks. Files live in
  `Application Support/ytm-downloads/{trackID}.m4a`.
- **Queue:** `AVQueuePlayer` rebuilt from a `playOrder` index permutation so
  shuffle/next/previous/repeat stay exact. Repeat-one uses
  `actionAtItemEnd = .none` + seek-to-zero.

## Build & run (Mac + Xcode 15+)

1. Start the backend (see `../yt-music-server/README.md`):
   `uvicorn app.main:app --port 8000` and `python -m app.worker`
   on a machine reachable from your iPhone (same LAN, or Tailscale).
2. Open `YTMusic.xcodeproj` in Xcode.
3. **Signing:** select the YTMusic target → Signing & Capabilities →
   set **Team** to your free Apple ID and change the bundle identifier
   (default `com.example.YTMusic`) to something unique, e.g.
   `com.yourname.ytmusic`.
4. Build & run on your iPhone (⌘R).
5. In the app's **Settings** tab, enter the server URL
   (e.g. `http://192.168.1.10:8000`) and the API token if you set
   `YTM_API_TOKEN`, then "Save & Test Connection".

## Sideload without the $99 developer account

- **Xcode (free Apple ID):** run from Xcode as above. The free provisioning
  profile expires after **7 days** — re-run from Xcode weekly to re-sign.
- **AltStore (recommended):** install AltStore on the iPhone, build the
  `.ipa` in Xcode (Product → Archive → Distribute → Ad Hoc / Development),
  sideload via AltStore. AltStore **auto-refreshes the 7-day certificate
  over Wi-Fi**, so the app never expires on you.

Free-account limits: no TestFlight, no App Store distribution, a handful of
sideloaded apps max — none of which matter for personal use.

## First-build checklist (things to verify in Xcode)

- Signing team / bundle ID is set (build fails otherwise).
- `NSAllowsArbitraryLoads` is on for plain-HTTP LAN servers; if you put the
  server behind HTTPS (recommended for Tailscale-off-LAN), you can tighten it.
- Background `audio` mode is in Info.plist (done) — verify it appears under
  Signing & Capabilities → Background Modes.

## API uncertainties (couldn't verify without Xcode/docs)

1. **Artwork URL pattern** `https://i.ytimg.com/vi/{youtubeID}/hqdefault.jpg` —
   the canonical YouTube thumbnail pattern, but not from the backend contract
   (the backend exposes no thumbnail endpoint). Falls back to a music-note
   placeholder if it 404s.
2. **`AVURLAssetHTTPHeaderFieldsKey`** for bearer auth on streams — the
   documented injection point; works for HLS/progressive, assumed fine here.
3. **Swift 6 mode:** the project targets Swift 5.0. If you flip the target to
   Swift 6 language mode, the `Task { @MainActor in … }` hops that capture
   `self` in `DownloadManager` may need `@Sendable` cleanup.
4. **Background downloads + auth:** the bearer token is baked into each
   `URLRequest`; if you change the token in Settings, already-enqueued tasks
   keep the old header (restart them).

## Deliberate v1 simplifications

- Playlist reorder = backend has no reorder endpoint, so move is
  delete + re-insert at position.
- No "play next / add to queue" — Play starts a new queue from the tapped list.
- Gapless is "best effort" via `AVQueuePlayer` (small gaps possible between
  ALAC tracks); true sample-accurate gapless would need a two-player engine.
- Search needs ≥ 2 characters; job polling is every 2 s (no WebSocket).
